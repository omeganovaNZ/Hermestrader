## 1. READ THIS FIRST — hard safety rules

These are not style preferences. Breaking one of them moves real orders on a live paper account.

- **`python position_manager.py` with NO flag places REAL ORDERS.** `run_position_management()`
  defaults to `dry_run=False` and calls `execute_trim` → `place_sell_order`. The cron job named
  "Trim Signal Alert" is not an alert; it places orders.
- **Read-only inspection only:** `check_trim_signals()`, `position_cap_signals()`,
  `add_signals()`, `theme_signals()`, `thesis_review_signals()`. Or
  `run_position_management(dry_run=True)`.
- **Never call** `execute_trim()` or `thesis_break_exit()` unless the user explicitly asks.
- **Never print, copy or commit the contents of `alpaca_config.txt`.** It holds live paper
  credentials. Before ANY push run:
  `git grep -nE "API_KEY|API_SECRET" -- .` — every hit must be a variable read, not a literal.
- **The repo is public on GitHub.** A live key was leaked once before by pasting it into a
  throwaway `test_*.py`. Keep throwaway scripts OUT of the repo (use the scratch dir) unless
  they are genuine durable assets.

## 4. The strategy as implemented

Config lives in code, not prose. **Read the code before quoting any threshold.**

`position_manager.trim_rules`:

```
profit_trim_pct    1.00    +100% ROI from the reference price
profit_trim_size   0.20    sell 20% of shares held
min_hold_days      183     held LONGER than 6 months
pullback_days      2       the last 2 daily closes each lower than the prior
trend_ma           200     must still be above its 200-day average
max_position_pct   0.10    trim cap — WINNERS ONLY
add_drawdown       0.20    a position 20%+ below its 52-week high is an ADD candidate
```

`alpaca_trader.max_position_pct = 0.08` — the ENTRY cap, deliberately below the 10% trim cap.
`portfolio_rules.MAX_THEME_PCT = 0.40` — the theme (sleeve) cap.

**Two trim mechanisms, and nothing else ever trims invested capital:**

1. **Profit trim.** Fires only when ALL FOUR hold: held >183d, +100% ROI, 2 consecutive down
   days, still above the 200-day average → sell 20%. Growth alone never trims. After a trim the
   ROI reference **re-bases to the trim price**, so the next trim needs another +100% from
   THERE — one trim event per doubling, never a cascade.
2. **Cap trim.** Over 10% of equity **and in profit** → trimmed back to the cap. Never fires on
   a loser. A symbol with a pending sell order is skipped.

**No automatic exit exists.** `thesis_break_exit()` is an explicit call, called by nothing.
Downside is managed by *reporting* only (`thesis_review`), because the owner's rule is that
invested capital is never trimmed on weakness.

**Owner's stated intent, verbatim:** *"I only want to trim stocks which I've held longer than 6
months, have had an over 100% ROI — at which point, if they continue to grow in value, don't
trim them. Only trim them when they've had 2-3 days of a decrease in shareprice (which doesn't
match the trend) and then issue a 20% trim of the total stock holding of that particular stock.
At no other time do I want to trim what has been invested."*

## 8. Known limitations — read before trusting the system

1. **An UNCLASSIFIED symbol escapes the theme cap entirely.** Alpaca's free tier has no sector
   field, so `portfolio_rules.THEMES` is hand-maintained. A new AI name not in the map buys
   through with no cap. A test forces every HELD symbol to be classified, and unclassified
   exposure prints on every scan — but it is a real hole, not a solved problem.
2. **The cap trusts Alpaca's position list.** If the broker omits a holding, exposure
   under-counts. Data-integrity dependency, not a bug.
3. **No fundamentals at all.** Every input is technical. For 1-2 year holds that is the biggest
   analytical gap. The free tier provides no earnings/revenue/valuation.
4. **The ensemble has never been validated out-of-sample.** 5 weighted layers; the skill records
   that the ranking once collapsed to pure momentum with three layers dead. Unknown whether that
   is fixed. A 5-layer ensemble with no test is complexity, not edge.
5. **The daily screener still runs 44 hand-picked names.** A market-wide screen (2,293 liquid
   names, `build_universe.py`) was built and works, but is not wired into any cron job.
6. **Thresholds are untested judgement calls:** 180 days may be short for a 1-2 year horizon,
   and STALE fires on ANY loss after a year (a -0.2% position is flagged like a -20% one).
7. **`test_alpaca.py` prints 12 characters of a 20-character API key.** Nothing is committed,
   but delete that print.
8. **The system has never measured its own edge.** No benchmark comparison, no drawdown series,
   no continuous correlation tracking. Every change is therefore a guess.

## 10. Where to go next (my assessment, in priority order)

1. **Fundamentals.** The single biggest gap. Even a crude quality gate (revenue growing,
   profitable, not over-indebted) via web research would filter the technically-attractive-but-
   broken names. One cron job already has the `web` toolset.
2. **Stage entries instead of one batch.** All 8 positions were bought at a single moment.
   Three tranches over weeks costs nothing and removes timing concentration.
3. **Validate or drop the ensemble.** Either test it out-of-sample or simplify to what is proven.
4. **Wire the market-wide screener into the daily job.** Built, validated, unused.
5. **Let it run unchanged long enough to produce a verdict.** The trim rule rests on 10 growth
   names and 13 holdings over one 12-month window. Churn resets the clock on whether any of this
   works.

**The honest caveat:** no strategy always increases. The goal is positive expected value with a
drawdown you can survive, and those trade against each other. The current book is one sector bet
wearing eight tickers, which is the opposite of resilience.
